## 2. v1 主候选 §3.1 的判定：放弃

### 2.1 撞车证据（按相关度排序）

| 工作 | 占了什么 | 与 §3.1 的重合 |
|---|---|---|
| **HERON — When Audio Matters: A Lightweight, Hierarchical Fusion Model for Speech and Non-Verbal Emotion Recognition**（Koudounas, La Quatra, Baralis；**ICASSP 2026**，SLP-P26.2；[摘要](https://exa.ai/library/publication/nx7vh8g5qx4)） | 原话："we demonstrate that **audio's primary value lies in disambiguating lexically neutral or ambiguous text**"；统一 speech + **NVV（笑/叹气）backbone**，残差交叉注意力注入文本模型；7.6M 可训练参数；全量微调 +3% F1；**优于 Speech-LLM**；在 OOD 对话数据上验证（引用了 MELD） | **§3.1 的核心主张原文级重合**。差别只剩：他们没有视频、不是 MLLM 骨干、没有显式路由器 |
| **EmoAgent-R1**（arXiv 2607.21013，2026-07） | MLLM 先当 Routing Agent 评估「歧义度 + 模态主导性」选推理策略，再当 Specialized Agent；RL 训练 | 占了「按模态主导性做路由」这个机制 |
| **PALLM — Aligning Paralinguistic Understanding and Generation in Speech LLMs via Multi-Task RL**（EACL 2026 Industry） | 明确针对「模型走 lexical shortcut、忽略副语言」；IEMOCAP/Expresso/RAVDESS 上超 Gemini-2.5-Pro / GPT-4o-audio 8–12% | 占了「文本捷径 vs 副语言证据」的问题陈述 |
| **TEXT — Text-routed Sparse MoE**（AAAI 2026） | 用文本做 MoE 路由的多模态情感分析 | 「文本路由」这个词已被用 |
| **NSV-Shift**（技术报告，22 对对照样本） | 同词不同非言语声（笑/哭/叹气/喘息）→ S2S 模型能否感知并调整回应 | 小规模，但说明这个切口已有人在做 |
| **Tian et al., ACII 2015 — Recognizing emotions in dialogue with disfluencies and non-verbal vocalisations** | 在 IEMOCAP/AVEC2012 上手工标注 填充停顿/填充词/口吃/笑声/呼吸，做情感识别特征 | **十年前的非 LLM 先例**，审稿人会直接拿来问「换了个骨干有什么不同」 |
| 其他 | MNV-17（17 类 NV 的中文 ASR 数据集）、voc2vec（NV 基础模型，ICASSP 2025）、「Exploring Adaptability of Large Speech Models to NVV」（CLiC-it 2025）、SpeechParaling-Bench（生成侧） | NV 检测器本身已有现成工具与基础模型，「NV-Cue Detector」不构成贡献 |

### 2.2 数据层面的硬伤（即使不撞车也难做）

- **IEMOCAP**：转写里已有 `[LAUGHTER]` / `[BREATHING]` 标记（HF 镜像可见），但 Tian et al. 2015 统计：**含笑声的语句仅 1.6%，含呼吸的仅 0.6%**（表演对话，NV 稀少）。"无话时刻"子集太小，撑不起主张。
- **MELD**：《老友记》带**罐头笑声轨（laugh track）**，是观众笑声不是说话人笑声。做"笑声检测"会先被它淹没（多篇 MELD 音频工作抱怨"actor's voice flooded by background laughter"）。要么先做音源分离（又一个工作量），要么主张不成立。
- v1 自己也承认 NV 标注层要自建，属数据贡献；现在连数据贡献的卖点也被 MNV-17 / NonverbalTTS 覆盖。

### 2.3 判定

**放弃。** 如果非要保留，只能缩成一个分析小节（"短句子集上 MLLM 性能差距"），不能当主线。

## 3. 对 v1 的事实修正（重要）

### 3.1 §2.1 的排除前提不成立

v1 原话："公开数据里'真·多标注者分布'与'音视频模态'不共存"。**核实结果：不成立。**

| 数据集 | 模态 | 标注者 | 分布形式 | 规模 | 获取 | 备注 |
|---|---|---|---|---|---|---|
| **DFEW**（ACM MM'20） | 电影片段 **V + A**（原始片段含音轨；MMA-DFER 等音视频方法直接从中抽音频） | **10 人/片段**（12 位专家轮换） | **7 维投票计数向量**，全部 16,372 片段都有 | 16,372 | 邮件申请（学校邮箱，模板见官网） | 标准 benchmark 只用 11,967 个"单标签"片段 → **约 27% 歧义片段被标准协议丢掉了**，这恰是研究对象 |
| **MAFW**（ACM MM'22） | 电影/剧/短视频 **V + A**，另有情感描述文本（不是转写） | **11 人/片段** | **11 维分布向量**（注意：是 0–1 置信分的汇总，**不是纯投票计数**；arXiv 2609.17130 明确说 MAFW 没有"可比的计数"） | 10,045 | 官网申请表 | 另有 32 类复合情绪子集（4,058 片段） |
| **IEMOCAP** | V + A + 转写 | **3 人/语句**，允许多选 | `EmoEvaluation/Categorical/` 子目录有**逐评估者**标签 | ~10k 语句 | 申请 | 全体一致仅 24%；**约 25% 语句无唯一多数票**，标准 4 类协议把它们丢了（Wu et al. 2022 Dirichlet 先验工作已利用） |
| **CREMA-D** | **V + A**（表演式） | **2,443 名众包者，95% 片段 >7 评分** | `finishedResponses.csv` / `tabulatedVotes.csv` 逐评分者；**且分三种呈现方式独立评分：只听 / 只看 / 视听** | 7,442 | GitHub 公开（git-lfs ~7.5 GB） | **唯一一个能回答"分歧来自哪个模态"的数据集** |
| MSP-IMPROV | V + A | ≥5 人众包 | 逐评估者 | 8,438 | 学术许可申请 | 备用 |

> v1 说 CREMA-D "HF 版只有音频、逐标注者评分只在原始仓库、且为表演式"——前两点属实但不是障碍（直接用原始仓库），第三点是限制而非否决（见 §5 对它的定位）。

### 3.2 DFEW 音频：有

官方 README 和论文描述的是"从 1,500+ 部电影手工截取的视频片段"，官方 benchmark 预处理（face++ 抽脸、16 帧插值）是**下游**步骤；MMA-DFER（音视频 DFER）仓库提供脚本"extract audio from the video files (in both DFEW and MAFW)"。**但 DFEW 没有转写文本**，所以它只能和同为 V+A 的数据集搭配（MAFW、CREMA-D），不能和 MELD/IEMOCAP 混搭成"三模态"——这符合 v1 的模态一致硬约束，只是一致在 V+A 上。

### 3.3 其他小修正

- v1 §2.1 引用的 *LLMs Capture Emotion Labels, Not Emotion Uncertainty*（arXiv 2604.27345）是纯文本（GoEmotions/EmoBank），结论"零样本 LLM 熵相关很弱、需要域内微调"对音视频版本是**有利的先验**，不是排除理由。
- v1 §2.9 的 DSPO（2609.36775）并没有用标注者分布，它的"分布"是用词典 VAD + 图像上下文**构造**的先验。不占 §2.1。

## 5. 新主候选：音视频 MLLM 的情感感知歧义建模与模态归因

### 5.1 问题

> **人对同一段音视频的情绪判断本来就不一致（DFEW 全体 10 人一致的只是少数；IEMOCAP 全体一致仅 24%）。现在的 MLLM 情感识别把这些分歧压成一个多数票标签来学、来评，于是：① 在人类分歧大的片段上过度自信（2609.17130 图 1 实测：分歧越大 ECE 越高）；② 说不出分歧来自哪里——是脸在说一件事、声音在说另一件事，还是本来就模糊。**

两个可检验的子问题：
1. **分布对齐**：MLLM 输出的情绪分布能否对齐人类投票分布（而不只是多数票对不对）？
2. **模态归因**：人类的分歧有多少可以归因到单一模态？模型能否预测"只看脸 / 只听声 / 视听合并"三种条件下的人类分布？——CREMA-D 的三条件评分是唯一能直接监督这一点的数据。

### 5.2 为什么它满足 v1 的约束

| v1 约束 | 满足情况 |
|---|---|
| 多模态 + 情感 + MLLM | 是：omni 类 MLLM（Qwen2.5-Omni / Qwen3-Omni / HumanOmni）+ V+A 输入 |
| 与 DTHFormer 平行 | 是：第一份是"视听刺激 + 生理信号 → 细粒度连续情感"；这份是"视听表达 → 人类感知分布与模态归因"。无生理信号，问题/方法/评测均不同 |
| ≥2 个数据集、模态一致 | DFEW + MAFW（都是 in-the-wild 电影 V+A）为主，CREMA-D（V+A，表演式）做归因监督/验证，IEMOCAP 可作第四个（V+A+T，只用 V+A 通道保持一致） |
| 不训练大模型 | 冻结 MLLM + LoRA / 或冻结编码器 + 轻量头，均可 |
| 有具名模块 + 消融 + 指标提升 | 见 5.3 |
| 呼应中期题目"细粒度 / 多模态协同" | 分布比硬标签细；模态归因就是"协同"的量化 |

### 5.3 方案骨架（沿用 DTHFormer 的"模块 + 消融"骨架）

```
输入: 视频 + 音频 (+ 可选对话上下文)
  ↓
冻结 omni-MLLM（LoRA）
  ↓
① Distribution Head（分布头）
   不读取 verbalized 数字，而是从情绪词 token logits / 隐状态输出 p̂ ∈ Δ^K
   目标：人类投票分布（DFEW 计数向量 / MAFW 置信分布 / CREMA-D 视听条件计数）
   损失：Dirichlet–Multinomial NLL（计数型）或 KL（比例型），按数据集选
  ↓
② Modality-Attributed Ambiguity Module（★核心模块，MAAM）
   对同一片段分别用 A-only / V-only / AV 三种输入前向（mask 另一模态），
   得到 p̂_A, p̂_V, p̂_AV 及各自熵 u_A, u_V, u_AV
   监督：CREMA-D 的三条件人类分布（直接监督）
   归因量：δ_conflict = JSD(p̂_A, p̂_V)；δ_gain = u_min(A,V) − u_AV
   一致性约束：模态一致时 u_AV ≤ min(u_A, u_V)；冲突时允许 u_AV 升高
  ↓
③ 输出：p̂_AV（分布）+ û（歧义度）+ 归因（A / V / 冲突 / 本征模糊 四类）
   可选：Chow 式选择性预测（弃答）
```

训练量级：LoRA（7B 级 omni 模型，单卡/双卡可跑）；或更省——冻结 MLLM 只训两个头。

### 5.4 指标归属（每个指标对应哪个输出）

| 输出 | 指标 | 对照 |
|---|---|---|
| 分布 p̂_AV | **KL / JS / Chebyshev / cosine / intersection**（LDL 标准 5 指标）对人类分布 | KL-to-mean 训练、CE-on-majority 训练、零样本 MLLM verbalized 分布 |
| 多数票 | WAR / UAR（**证明不掉准确率**，不是主张） | DFER-CLIP、MAE-DFER、S2D、Emotion-LLaMA、HumanOmni |
| 歧义度 û | **Spearman ρ 对人类投票熵**；高/低歧义二分 AUROC | **2609.17130 在 DFEW 上 ρ=0.52（纯视觉）← 必须超过的数字** |
| 模态归因（MAAM） | CREMA-D 上：p̂_A / p̂_V 对 A-only / V-only 人类分布的 KL；**冲突检测 AUROC**（A-only 多数票 ≠ V-only 多数票的片段） | 去掉 MAAM 的单路模型；随机归因 |
| 校准 / 选择性预测 | ECE；AURC；coverage 0.9/0.8 下的 selective risk | 2609.17130：ECE 0.036 / AURC 0.108（DFEW 官方 5 折） |
| 泛化 | CREMA-D 训练的归因头 **零样本迁移**到 DFEW / MAFW（看 δ_conflict 高的片段是否对应人类高熵）；DFEW → MAFW | 报告 |

消融表（至少）：去音频 / 去 MAAM / DM→KL→CE / 去一致性约束 / verbalized vs logits vs head 三种分布读出 / LoRA vs 冻结。

### 5.5 必须正面处理的近邻工作（差异点要写进 related work 第一段）

| 近邻 | 它做了什么 | 我们的差异 |
|---|---|---|
| **Predicting Human Disagreement for Calibrated DFER**（arXiv **2609.17130**，2026-09，短文） | DFEW 投票计数 + Dirichlet–Multinomial；歧义头 ρ=0.52；Chow 式弃答；ECE −30%、AURC −15%；**纯视觉**（冻结 VideoMAE-B）；明说 "DFEW 是唯一有计数的数据集" | ① **加入音频**与 omni-MLLM；② **模态归因**（他们没有，也没有能监督归因的数据）；③ 用 CREMA-D 三条件评分做归因监督；④ 多数据集（他们 MAFW 只做了开集辅助分析）。**最大风险**：若加音频后 ρ 没有明显超过 0.52，这条线就只剩归因一个卖点 |
| MultiEmo-Bench（2605.14635） | 图像，20 人/图，MLLM 分布预测评测 | 图像 → 音视频；评测 → 方法 |
| Video2Reaction（2607.06875） | 视频 → 观众**诱发**反应分布（来自评论，LLM 自动标注），LoRA VLM + KL | 诱发 vs **感知**；评论派生 vs 真人投票；无音频归因 |
| LLMs Capture Labels Not Uncertainty（2604.27345） | 纯文本，零样本 LLM 熵相关弱 | 作为动机引用 |
| MIDAS（WACV'24 / 2506.20867） | DFEW 软标签做 mixup 增强 | 增强手段 vs 建模目标 |
| Wu et al. 2022（2203.04443） | IEMOCAP 逐评估者标签 + 语句级 Dirichlet 先验（语音） | 单模态、非 LLM；可作 IEMOCAP 上的基线 |
| EmoMM（ACL 2026 Findings） | 冲突/缺失下的 MLLM 评测与注意力引导 | 他们的"冲突"是构造的（替换模态），我们的分歧是**人类真实标注**；他们不预测分布 |

### 5.6 风险与止损

1. **增量风险**（最大）：2609.17130 已把"DFEW + DM + 弃答"做了。止损条件见 §7 第一项——如果 omni-MLLM 加音频在 DFEW 上歧义预测 ρ 提不到 0.55+，且 CREMA-D 上冲突检测 AUROC < 0.75，**放弃本线**。
2. **CREMA-D 是表演式**：只把它用作归因模块的监督源与验证集，不拿它当主 benchmark；主结论在 DFEW/MAFW 上报。
3. **MAFW 分布是置信分不是计数**：训练目标按数据集切换（DM for DFEW/CREMA-D，KL for MAFW），论文里明确说明。
4. **数据申请周期**：DFEW、MAFW 都要邮件/表单，CREMA-D 立刻可拿 → 先用 CREMA-D 开工。
5. **投稿定位**：ICASSP/Interspeech 短文够，ACM MM / ACL Findings 需要归因部分做扎实；TAFFC 正刊需要再加一个贡献（例如把歧义估计用于主动标注/数据清洗）。

## 8. 关键提醒（在 v1 §7 基础上增补）

1. **不要再在 MELD/IEMOCAP 上找"非言语"缝隙**，HERON + PALLM + Tian 2015 三面夹击。
2. **CREMA-D 只做归因监督/验证，不做主 benchmark**，否则会被批"表演式"。
3. **2609.17130 必须在论文第一页就被引用并说明差异**，装作没看见会被审稿人当场抓住。
4. **分布读出方式要固定**：verbalized 数字（会坍缩）、label-token logits、独立分布头三种都报，但主结果用一种。
5. **"分歧 ≠ 噪声"**：人类高熵片段不等于该弃答（干净但本征模糊的片段应当输出宽分布而不是拒答）；2609.17130 已把这点讲清，我们要沿用而不是倒退。
6. 模态一致性在本线上是 **V+A**；不要为了凑"三模态"把 MAFW 的情感描述文本当转写用。

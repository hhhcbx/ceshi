# 小艺工作流试运行 error + 追踪为空 — 排错指南

## 现象含义

| 现象 | 通常说明 |
|------|----------|
| 直接报 `error` | 工作流**未成功启动**，或**第一个节点之前就校验失败** |
| 追踪节点为空 | 图引擎**还没跑进任何节点**，不是某个中间节点逻辑错 |

因此优先查：**开始节点入参、图结构合法性、保存/上架状态**，而不是先怀疑大模型 Prompt。

---

## 第一步：拿到真实错误信息（必做）

追踪为空时，错误往往在别处：

1. 浏览器 **F12 → Network（网络）**，点「试运行」，找失败的请求（红色）
2. 看 Response 里的 `message` / `desc` / `code`
3. 或看页面上 error 旁是否有 **展开详情**、**复制错误码**

把错误码或 message 记下来，比盲猜快 10 倍。

---

## 第二步：开始节点入参（最高频原因）

### 必填项（缺一不可）

试运行面板里，以下 **Object 类型** 必须填**合法 JSON**：

- `candidate_profile`
- `paper_facts`
- `session_state`
- `conversation_trace`

### 常见踩坑

| 问题 | 后果 |
|------|------|
| 必填 Object **留空** | 启动即 error，追踪为空 |
| 粘贴了 `_test_meta`、`_source` 等测试用字段 | 若开始节点未定义子字段，可能校验失败 |
| `is_finished` 写成字符串 `"true"` | 选择器 Boolean 判断异常（可能走错分支或条件报错） |
| JSON 少逗号、多引号 | 解析失败，直接 error |
| 只填了 `userFields`，但平台还要求 `USER_INPUT` 等 | 视你开始节点配置而定 |

### 推荐做法

用 `test_data_TC01_试运行专用.json`：**整文件内容按字段分别粘贴**到试运行对应输入框（不要包一层 `userFields` 外壳，除非 UI 明确要求）。

`session_state` 示例（注意 `is_finished` 是布尔值）：

```json
{
  "session_id": "sess_001",
  "is_finished": true,
  "kill_switch_reason": "",
  "current_stage": "Z",
  "total_rounds": 3
}
```

---

## 第三步：图结构检查

在画布上确认：

- [ ] **只有一条从「开始」出发的主路径**能到达当前试运行的「结束」
- [ ] **没有悬空节点**（未连入开始→结束链路的节点，部分平台会校验失败）
- [ ] 选择器 **三条分支都有下游**（KILL_SWITCH、NORMAL、default/否则）
- [ ] 两个「结束」节点分别只接各自分支，**不要交叉连线**
- [ ] 修改后点了 **保存**，必要时先 **上架** 再试运行（以平台提示为准）

---

## 第四步：二分法缩小范围（追踪仍为空时）

### 4.1 最小冒烟（5 分钟）

临时新建或复制一份工作流，只保留：

```text
开始 → 输出（模板写「hello」）→ 结束
```

- 若仍 error + 追踪空 → **账号/平台/浏览器/工作流权限**问题，与工作流逻辑无关
- 若成功 → 问题在你当前复杂图或入参

### 4.2 逐步加回节点

按顺序加，每加一段试运行一次：

```text
1. 开始 → 评分量表 → 结束（结束引用 score_rubric/output）
2. + 轨迹分组 → 结束
3. + 选择器 → 结束（先只连 default 到简单输出）
4. + 大模型 → …
```

**第一次报错的那个节点**就是问题区间。

---

## 第五步：按节点类型逐项核对

### 选择器

- `kill_switch_reason` 子字段类型：**String**
- `is_finished` 子字段类型：**Boolean**（不是 String）
- NORMAL 分支：`is_finished == true` **且** `kill_switch_reason == ""`

### 文本处理节点

- 上游 Object 未传入时，拼接结果可能是空或 `{变量名}` 原样——一般不会导致「追踪为空」，但会导致大模型输入异常

### 大模型节点

- **System Prompt + User Prompt** 都已填写
- User 里 `{grouped_conversation_trace}`、`{score_rubric}` 等在「输入」里**已手动关联**
- 输出格式：**Markdown**（与配置一致）
- 模型是否在该环境**可用**（失效模型有时整流失败；追踪可能仍为空或停在启动前）

### 输出节点（你刚修过的）

三者必须一致：

```text
输入参数名  ==  模板 {{变量名}}  ==  上游绑定的字段
```

| 输出节点 | 输入参数名 | 模板 |
|----------|------------|------|
| 报告流式输出 | `validated_markdown_report` | `{{validated_markdown_report}}` |
| 未完成流式输出 | `markdown_report` | `{{markdown_report}}` |

### 结束节点

- `stepInfo`：填固定文字，**不要引用流式变量**
- `outputId`：可留空
- 若结束节点也报「参数不能为空」，先让结束节点**只接一个必填字段**试跑

---

## 第六步：两条分支分别试

不要混测。

**测 NORMAL（上支路）**

- `is_finished`: `true`
- `kill_switch_reason`: `""`
- 数据用 `test_data_TC01_试运行专用.json`

**测 default（下支路）**

- `is_finished`: `false`
- `kill_switch_reason`: `""`
- 应走未完成占位，**不调大模型**，更容易先跑通

若下支路能通、上支路 error，问题在 **大模型或后处理**；若两条都 error，问题在 **开始/选择器/全局配置**。

---

## 第七步：仍无法定位时提供给支持/他人的信息

1. Network 里失败请求的 **完整 Response**
2. 开始节点 **参数截图**（含类型、是否必填）
3. 画布 **全图截图**（含连线）
4. 试运行时填的 **session_state** 和 **conversation_trace** JSON
5. 是点上支还是下支、选 NORMAL 还是 default

---

## 快速对照表

| 症状 | 优先检查 |
|------|----------|
| error + 追踪空 | 开始节点必填 JSON、保存、F12 错误详情 |
| 追踪有开始，无后续 | 选择器条件/分支连线 |
| 停在大模型 | 输入未绑定、模型不可用、Prompt 变量名 |
| 停在输出 | 模板变量名 ≠ 输入参数名 |
| 结束报错 | stepInfo 引流式变量、结束入参未绑 |

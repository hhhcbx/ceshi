# 输出格式与呈现规范

指标查询结果的字段规范、筛选条件语义映射、表格与图表呈现模板。

## 一、指标默认返回字段

除非用户特殊指示，每条指标返回以下字段：

| 字段 | 含义 | 备注 |
|---|---|---|
| `measureType` | 度量类型 | |
| `nameCn` | 指标中文名 | 必有 |
| `nameEn` | 指标英文名/编码 | 必有 |
| `description` | 描述 | |
| `type` | 指标类型 | 常见值：BASIC（基础）/ DERIVED（衍生）/ COMPOSITE（复合） |
| `level` | 指标级别 | 常见值：GOLD（黄金）/ HEALTH（健康）/ NORMAL（普通） |
| `tag` | 标签 | |

规则：

- **全空列省略**：某字段在**本次全部结果**中都为空（null/空串/空数组）→ 整列不展示，也不要在文字里逐条写「tag：无」。
- **用户指定优先**：用户明确说了要哪些字段（如「只要中文名和描述」），以用户为准。
- 字段值原样展示，不要翻译或改写规范值（GOLD 就写 GOLD，可在括号里补中文，如 `GOLD（黄金）`）。

## 二、筛选条件语义映射

用户的自然语言限定词 → 指标字段过滤条件。匹配一律**大小写不敏感**。

### level（级别）

| 用户可能的说法 | 过滤条件 |
|---|---|
| 黄金指标、黄金、gold、金牌指标 | `level = GOLD` |
| 健康指标、健康、health | `level = HEALTH` |
| 普通指标、一般指标、normal | `level = NORMAL` |

### type（类型）

| 用户可能的说法 | 过滤条件 |
|---|---|
| 基础指标、原子指标、basic | `type = BASIC` |
| 衍生指标、派生指标、derived | `type = DERIVED` |
| 复合指标、组合指标、composite | `type = COMPOSITE` |

### 注意事项

- 当前指标数据较规范，以上取值可直接用；但**字段实际取值可能存在变体**（如 gold / GOLD / goldLevel）。过滤时先对实际数据做大小写不敏感的包含匹配，若发现新取值形态，向用户说明后按语义归类。
- 映射表未覆盖的说法：按语义选最接近的规范值，并**在回答中明确写出实际使用的过滤条件**（如「按 level=GOLD 筛选」），不要静默猜测。
- 筛选后为空时：报告总数与条件（「共找到 12 个指标，其中 0 个满足 level=GOLD」），并给出实际存在的取值分布（如「现有 level 取值：HEALTH×3、NORMAL×9」）。

## 三、指标列表呈现模板（Markdown 表格）

按「分类路径 → 逻辑实体」分组，**每个逻辑实体一张表**。结构如下：

```markdown
## 查询结果

**查询**：小艺的黄金指标
**命中路径**：业务&平台 > 小艺（business_and_platform.CEL）
**筛选条件**：level = GOLD（黄金指标）
**结果**：2 个逻辑实体，共 2 个指标

### 智慧视觉hivision接口日志（hivision_interface）

| 中文名 | 英文名 | 类型 | 级别 | 度量类型 | 描述 |
|---|---|---|---|---|---|
| 智慧视觉接口_成功率 | hivision_interface_request_success_rate | COMPOSITE | GOLD | ... | 统计智慧视觉接口 result in (T) and code in (0,200) 的请求量占比 |

### 智慧视觉小艺翻译接口信息（hivoice_bot_interface）

| 中文名 | 英文名 | 类型 | 级别 | 度量类型 | 描述 |
|---|---|---|---|---|---|
| 智慧视觉小艺翻译接口_成功率 | hivoice_bot_interface_request_success_rate | COMPOSITE | GOLD | ... | 智慧视觉小艺翻译接口 flag in (T) 的请求量占比 |
```

要求：

- 顶部**关键信息头**必须有：查询内容、命中路径（中文路径 + 点分 ID）、筛选条件（如有）、结果统计。
- 表列顺序建议：中文名、英文名、类型、级别、度量类型、标签、描述（描述放最后，因为最长）。全空列省略。
- 没有指标的实体单独一句话带过（「X、Y 两个实体暂未定义指标」），不占表格。
- 实体很多时按相关性排序，最相关的在前。

## 四、图表呈现规范（趋势/数值类查询）

> 适用于意图 C（指标数值/趋势）。当前指标数值源尚未接入，本节在数值能力就绪后启用；结构先定死，届时 agent 直接照此执行。

### 总体结构

一张**可下载的完整图**由「信息头 + 图表」组成，用 agent 原生画图能力生成（不外接 MCP 工具）：

1. **信息头**（图上方，作为图的一部分渲染，而不是聊天文字）：
   - **标题**：`<对象> <指标> <维度>趋势`，如「微信 每日活跃设备数 趋势」
   - **维度**：时间粒度（天/小时/月）
   - **指标**：指标中文名（英文名），如 `单框_应用日活设备数（xxx_dau_device_count）`
   - **筛选条件**：起止时间、维度过滤（如 应用中文名称=微信）、排序（升序/降序）、条数限制（如 limit 100）等，全部列出
2. **图表主体**：
   - 趋势 → 折线图；分类对比 → 柱状图；占比 → 饼图；默认折线。
   - 横轴 = 时间（按维度粒度），纵轴 = 指标值，标注单位（如有）。
   - 多序列（如多个应用对比）时加图例。

### 生成方式

- 用 agent 原生的图表/代码绘图能力（如内置的 matplotlib/ECharts/artifact 渲染），生成**单个自包含的图片或 HTML**，保证用户可直接下载保存。
- 信息头直接绘制在图内顶部（图题+副标题区域），确保下载后的图自带上下文，脱离聊天记录也能看懂。
- 数据行数超过限制（如 limit 100）时在筛选条件中注明实际截断。

### 示例（「近一个月微信每日活跃设备数趋势」）

图内信息头：

```text
标题：微信 每日活跃设备数 趋势
维度：天
指标：单框_应用日活设备数（single_box_app_dau_device_count）
筛选条件：2026-06-22 ~ 2026-07-22；应用中文名称=微信；按时间升序；限制 100 条
```

其下为折线图：横轴=日期（天），纵轴=日活设备数。

### 表格兜底

- 若原生绘图能力不可用或数据不适合作图（如仅几个离散值），退化为 Markdown 表格 + 同样的关键信息头。
- 无论图或表，**关键信息头永远不能省**。

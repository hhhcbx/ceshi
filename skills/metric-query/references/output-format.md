# 本体指标查询输出规范

## 1. 普通指标目录

必须给出查询范围：

```text
起始节点：<operation_object ID>
拓扑深度：1（仅直接关联指标）
结果：共 <N> 个去重指标
```

建议表格：

| 指标名称 | 指标 ID | 服务 ID | 关系/路径 |
|---|---|---|---|

节点字段为空时不编造；全空列可以省略。同一指标通过多条路径出现时只列一条指标记录，并在关系/路径中保留多条证据。

## 2. 数值或趋势查询

必须说明：

- 起始 `operation_object` ID；
- `max_depth=1`；
- 最终指标名称和真实 ID；
- 指标与起始节点之间的关系或路径；
- 实际开始、结束时间和时区；
- 数据接口的真实结果。

单值直接展示；时间序列可用表格或云 Agent 原生绘图能力展示。返回空时写明“该指标在所选时间范围内无数据”，不得补零。

## 3. 多候选澄清

仅展示足以让用户区分的字段：

| 序号 | 指标名称 | 指标 ID | 需要确认的差异 |
|---|---|---|---|

明确说明尚未调用数据查询接口。不得以“第一个”“有数据的一个”代替用户选择。

## 4. 缺少叶子节点 ID

输出必须包含：

1. 已识别的指标和时间表达；
2. 缺少的是 `operation_object` 叶子节点 ID；
3. 当前工具不能按业务名称搜索叶子实例；
4. 请求用户直接提供 ID；
5. 明确说明没有根据名称猜测 ID。

## 5. 拓扑查询

顶部显示起始节点和实际 `max_depth`，随后按路径展示：

```text
<left node id> --<edge type>--> <right node id> [<tags>]
```

不得把 `related_to`、`contains`、`belongs_to` 等不同关系改写成同一种“属于”。不得把深度 2、3 发现的指标描述为起始节点的直接指标。
